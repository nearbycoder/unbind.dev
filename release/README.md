# Versioned and signed releases

Each stable tag matching the version in `Cargo.toml` builds and publishes the six platform executables. The versioned download root is `https://unbind.dev/downloads/releases/<version>/` and `latest` selects the current published GitHub release. Versioned assets include `SHA256SUMS`, the signed `release.json`, its detached `release.json.sig`, and the package manager recipes.

```sh
unbind update --check
unbind update
unbind update --version 0.2.0
unbind rollback
```

The updater verifies the manifest signature with the Ed25519 public key pinned in the binary, then checks the selected executable's size and SHA-256. After installing, it keeps one verified local backup for rollback. Use the original package manager for installations it manages.

## Maintainers

Use a Git tag `vX.Y.Z` on the commit whose `Cargo.toml` version is `X.Y.Z`. GitHub Actions signs the manifest using the secret `UNBIND_RELEASE_SIGNING_KEY`. Its value is an Ed25519 private key in PEM format. The workflow derives the public key and compares it with `release/public-key.hex` before signing. Keep the private key in a secret manager and enable immutable releases in the repository's settings before publishing a tag.

The draft release gathers all assets before publication. The package manager recipes are generated by [package-release.py](../scripts/package-release.py) from the release binary bytes. See the [package manager installation instructions](../packages/README.md).
