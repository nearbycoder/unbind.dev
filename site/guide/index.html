Install Unbind

Install Unbind on both computers. Either can use the desktop app or the CLI. An invite works with both.

Desktop app

Choose the archive for your operating system and processor from desktop downloads. Extract it before opening the app.

  • macOS 13 or later. Move Unbind.app to Applications and open it. The app uses an ad-hoc signature, so macOS may ask you to approve it in Privacy & Security.
  • Windows. Open Unbind.exe. It runs under your user account. Windows may display a publisher prompt on first launch.
  • Linux. Open Unbind/unbind-desktop. The build targets Ubuntu 24.04 or a compatible glibc distribution and needs X11 or Wayland and Vulkan graphics. The archive includes an optional per-user installer. You can enter file paths by hand on systems without an XDG file picker.

CLI

On macOS and Linux, the installer places the binary in ~/.local/bin by default. Add that directory to your PATH if your shell needs it.

curl -fsSL https://unbind.dev/install.sh | sh

In Windows PowerShell, run this installer.

irm https://unbind.dev/install.ps1 | iex

The downloads page also has standalone CLI binaries and instructions for Homebrew, Scoop, and the WinGet manifest.

Share and connect

This example shares a web service already running on port 3000. The computer running it is the host. The other computer is the guest.

On the host

Open Share, enter 3000 in Port or address, and select Create invite. Use Copy invite to send the link to your guest. Keep Unbind open while they use the service.

On the guest

Open Connect, paste the invite, and enter 8080 in Listen on. Select Connect. Once the session is connected, open http://127.0.0.1:8080 in a browser on the guest computer.

Use a terminal on either computer

On the host, run the share command and copy the link it prints.

unbind share 3000

On the guest, replace <link> with the complete link and keep the quotes.

unbind connect '<link>' --listen 8080

The guest uses its own local port. Open 127.0.0.1:8080 on the guest. If that port is in use, pick another and point your browser or service client there.

TCP, UDP, and SSH

A bare service port refers to 127.0.0.1 on the host. You can also enter a host address such as 192.168.1.20:5432 for a service reachable by that computer. On the guest, a bare listening port binds to 127.0.0.1.

Share several services in one invite

Give each route a name with letters, numbers, hyphens, or underscores. The guest uses the same name and protocol and chooses a free local port.

Example port mapping
RouteProtocolHost targetGuest port
webTCP30008000
apiTCP80818001
dnsUDP53538053

On the host, open Share → Advanced sharing. Clear Port or address for a named-only share. Enter web=3000 and api=8081 on separate lines under Named TCP services, and enter dns=5353 under Named UDP services.

On the guest, open Connect → Named routes. For this named-only example, clear Listen on. Enter web=8000 and api=8001 under Named TCP ports, and enter dns=8053 under Named UDP ports.

For the same share in the CLI, run this on the host.

unbind share --tcp web=3000 --tcp api=8081 --udp dns=5353

On the guest, assign local ports to those names.

unbind connect '<link>' --tcp web=8000 --tcp api=8001 --udp dns=8053

Use your usual service client

  • Web app or API. Open the TCP listener address in a browser or follow the app’s normal HTTP or HTTPS setup.
  • Database. If you share TCP port 5432 and the guest listens on 15432, the guest points its database client at 127.0.0.1:15432 and signs in as usual.
  • SSH. Share the host’s SSH port, typically 22. If the guest chooses 2222, the SSH client connects to 127.0.0.1 on port 2222 with the host’s usual SSH credentials.

For CLI integration, OpenSSH can use Unbind as a ProxyCommand. This example uses a simple share created with unbind share 22.

ssh -o "ProxyCommand=unbind connect '<link>' --stdio" user@host

Manage invite access

The complete invite grants access according to the share’s settings. Send it privately. A QR code carries the same invite, so share it with the same care.

Send a link or display a QR code

Use Copy invite or Show QR code after creating an invite on desktop. In the CLI, pass --qr to unbind share, unbind send, or unbind invite. The recipient still opens the invite in Unbind on their computer.

To open invites from a browser in the desktop app, choose Settings → Enable desktop links. From the invite’s join page, select Open in Unbind, review the invite in the app, and connect. If you use the CLI as your link handler, run unbind register-link and confirm each invite in the terminal.

Limit an invite’s lifetime and audience

In Share, set Expires after (minutes) to close the invite and its connections after a set time. Turn on One guest only to let the first successful guest use that link. If a used single-guest invite can no longer reconnect, ask the host for a fresh one.

With the CLI, set the lifetime in seconds. This invite lasts ten minutes and admits one successful guest.

unbind share 3000 --expires-in 600 --single-use

Approve guests and remember a verified device

Set Approve each guest before creating a share. In Sessions, choose Approve or Decline when a guest requests access. Guests can turn on Identify this device to the host before connecting. For a device you recognize, Approve and remember lets its verified identity skip future approvals on your computer.

For a CLI share, add --approve. On the guest, add --identify to unbind connect to present its Ed25519 device identity. A guest using the CLI can run unbind identity and share the public fingerprint with the host for comparison. Find the pending peer and share IDs with unbind status before approving or declining.

unbind approve SHARE_ID PEER_ID --remember

Omit --remember for one approval, or run unbind deny SHARE_ID PEER_ID to decline.

Issue and revoke separate guest links

Use New invite on a share in Sessions to give another guest a separate URL. It takes its lifetime and one-guest setting from the current Share form. Use Revoke on that invite to close its link and disconnect its guests. Stop ends the entire share.

unbind invite SHARE_ID --expires-in 600 --single-use
unbind revoke SHARE_ID INVITE_ID

Send and receive files

Offer one file to one recipient. The file goes over the encrypted connection between peers. Unbind verifies its SHA-256 before saving it to the destination.

  1. On the sending computer, open Files and use Choose file or enter its path. Select Create file invite, then send the link.
  2. On the receiving computer, paste the link in File invite link. Choose a new destination under Save as and select Receive file.
  3. Keep both clients running until the transfer finishes. Choose a new filename if the destination already exists.

If you opened the link with Open in Unbind, go to Files to receive it. The app fills in the file invite link.

On the sending computer with the CLI, run this command.

unbind send ./report.pdf

On the receiving computer, provide the invite and the new destination.

unbind receive '<link>' ./report.pdf

Sessions and saved profiles

Open Sessions to see active shares and connections, pending approvals, selected network paths, and traffic totals. The CLI can report the same local session status in a format suitable for scripts.

unbind status --json

Reconnect on the same local address

With Reconnect after an interruption enabled, the guest keeps the local listener while Unbind tries to restore the tunnel. Existing TCP connections may close during the interruption. Reopen your service client’s connection once the session is back. CLI connections retry after interruption by default. Use --no-reconnect to exit instead.

Reuse a share configuration

Use Saved profiles in the desktop Share view to save a configuration. Give it a name and select Save profile. Later, choose Load and create an invite with those settings.

For the CLI, save a profile in unbind.toml. This example shares two TCP services under the same invite and sets a one-hour lifetime.

[shares.dev]
expires_in = 3600

[shares.dev.tcp]
web = "3000"
api = "8081"

Run one of the following on the host. Use --config PATH to choose a different profile file.

unbind share dev
Start in the foreground.
unbind start dev
Start a background share.
unbind start dev --at-login
Start the background share and register it to start at user login on supported systems.
unbind stop dev --at-login
Stop the background share and remove its login registration.

How a direct connection is made

  1. Meet through rendezvous. The host and guest exchange short-lived connection descriptions. The invitation’s authentication secret lives in the part of the link after #. The clients use it to authenticate the offer and answer.
  2. Find a direct UDP path. STUN helps each peer learn the public UDP address its network presents. ICE checks candidates such as local and public addresses to find a working path between the computers.
  3. Exchange traffic peer to peer. Application traffic and files travel through the encrypted WebRTC data channel between the peers. The rendezvous service handles setup. An established tunnel can keep running during a rendezvous outage.

Run diagnostics on both networks

In the desktop app, choose Settings → Run diagnostics. In the CLI, run unbind doctor. The checks report rendezvous reachability and STUN results over IPv4 and IPv6. A successful diagnostic shows those parts are reachable. A live attempt across the two networks tests the direct path.

unbind doctor --json

Double NAT and restricted networks

Unbind needs a direct UDP path. Double NAT, carrier-grade NAT, and restrictive firewalls can prevent ICE from finding one. When direct checks fail, Unbind reports a connection failure. If both peers are on the same local network, try LAN mode.

Configure a reachable UDP endpoint

Keep the optional network fields blank for automatic discovery. If you control the router and already forward an external UDP port, set Local UDP bind and Public UDP endpoint in Settings. Forward the external UDP port to that local bind address and port. The public address and bind must use the same IP family.

This CLI example advertises a public address on UDP 45000 that the router forwards to local UDP 40000. Replace PUBLIC_IP with your reachable address.

unbind share 3000 --udp-bind 0.0.0.0:40000 --public-endpoint PUBLIC_IP:45000

For a router that supports PCP, set PCP gateway to the router’s local IP and use a Local UDP bind. Unbind requests a temporary mapping and renews it while in use. Choose either a public endpoint or a PCP gateway for a given connection.

unbind share 3000 --udp-bind 0.0.0.0:40000 --map-port 192.168.1.1

Use another rendezvous or STUN service

In desktop Settings, set the Rendezvous server to an HTTPS origin and STUN servers to a comma-separated list of stun: URLs or none. Select Save settings. The guest uses the rendezvous origin in the invite. For CLI hosts, use --server or UNBIND_SERVER and set --stun or UNBIND_STUN.

The source repository includes the unbind-web rendezvous server and a Dockerfile. It keeps short-lived room state in memory. Run a single instance and serve it over HTTPS for peers outside your local network. Build and operate rendezvous from source.

Share offline on a LAN

Use LAN mode when both computers can reach each other on the same private network. The host runs rendezvous locally and the link points to its private address. Both clients use local candidates and can connect without internet service.

On desktop, choose Share → Advanced sharing → Local network only before creating the invite. The guest connects using that invite as usual.

unbind share 3000 --lan

If the host has several interfaces, the CLI can select a specific local address with --lan-bind IP:PORT. Choose an address the guest can reach. Guest Wi-Fi isolation or a local firewall can still prevent the peers from reaching each other.

Troubleshoot a connection

The invite looks invalid or stays on Connecting

Copy the full invite, including the part after #. Confirm the host is still running the share and review Sessions for pending approval. If an invite has expired, been revoked, or been used by its first guest, ask the host to issue a new one.

Unbind connects, but the service won’t open

Check that the host can open the original service locally. On the guest, use the listening port shown in Sessions. For a named share, check that the route has the same name and protocol on both peers. Use the service’s usual client, protocol, and credentials.

The tunnel works at home, then fails across networks

Run diagnostics on both networks and retry across those same networks. If direct UDP remains unavailable, try a network that can reach the other peer directly. A reachable UDP port mapping can help when you control the router. Double NAT can require reachability through more than one router.

The guest cannot bind its local port

Change Listen on or the relevant named port to a free local port. Connect again, then update your browser or service client to that port.

The browser’s Open in Unbind button does nothing

In the desktop app, use Settings → Enable desktop links. You can also use Copy invite on the join page and paste the full link into Connect manually.

A file transfer fails before saving

Confirm the sender still has the file invite open. Choose a destination that does not already exist and make sure its directory is writable. If the file invite was consumed during the failed attempt, ask the sender for a new one.

Verify and update

Desktop archives

Get the archive and its matching unbind-desktop-SHA256SUMS and unbind-desktop-SHA256SUMS.sig files from the same version in the release archive. In that folder, save a trusted copy of Unbind’s pinned Ed25519 public key as public-key.hex.

In a POSIX shell with OpenSSL 3 and xxd, convert the key to DER and verify the checksum file’s signature.

{ printf '%s' 302a300506032b6570032100; cat public-key.hex; } | xxd -r -p > unbind-public.der
openssl pkeyutl -verify -pubin -keyform DER -inkey unbind-public.der -rawin \
  -in unbind-desktop-SHA256SUMS -sigfile unbind-desktop-SHA256SUMS.sig

Compare the SHA-256 of your archive with the corresponding line in the verified checksum file. Run sha256sum ARCHIVE on Linux, shasum -a 256 ARCHIVE on macOS, or Get-FileHash -Algorithm SHA256 -Path ARCHIVE in Windows PowerShell. Replace ARCHIVE with your downloaded filename.

To update the desktop app, quit Unbind, extract the archive for the new version, and replace the previous app.

CLI installation and updates

The CLI installers verify the published SHA-256 before installation. The verification commands compare the installed executable with the currently published binary. If you installed to a custom UNBIND_BIN_DIR, use that same directory when verifying.

Use these commands with a standalone CLI installation. For installations managed by a package manager, update through the matching package manager.

unbind update --check
Check for a published signed version.
unbind update
Verify and install the latest signed version.
unbind update --version 0.3.0
Select an exact published version.
unbind rollback
Restore the executable saved before the last update.
